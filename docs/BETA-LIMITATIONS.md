# Beta 功能矩阵与已知限制（v3.0.0-beta.1）

> 本文件描述 `3.0.0-beta.1`（开发者预览）实际可依赖到什么程度。
> 结论先行：**beta 可用于 mock 体验、开发与离线验证；真实微信的读取/OCR/自动发送尚未实机验收。**

## 1. 功能矩阵

| 功能 | beta 状态 | 说明 |
| --- | --- | --- |
| mock 通道（入站模拟 / 发送记录 / 审计） | ✅ 离线验收 | `verify:api` 25/25；不接触真实微信 |
| 人格模拟与 mock 对话 | ✅ 离线验收 | 内置 4 个人格 + 自定义/导入；mock 下可走通回复流程 |
| DSH LLM 生成回复 | ✅ 可用（需配置模型） | 费用由你的模型服务商决定；无模型时不能生成真实回复 |
| 本地记忆与长期摘要 | ✅ 代码+单测 | 摘要调用受预算/每日上限约束 |
| 白名单/时段/频控/预算/熔断/去重 | ✅ 代码+单测 | 本地规则先拦截，不花 token |
| 发送可靠性（10 态状态机 + `sendOperationId` 幂等账本） | ✅ 代码+单测 | 真实故障路径（重启/超时/子进程异常）未实机演练 |
| `sendMode`（`auto`/`draft`/`confirm`，草稿人工批准） | ✅ 离线验收 | beta 安全模式默认下仍可用 mock 演练 |
| desktop Windows OCR（WinRT 主引擎 + 同帧 + 基线/ack + 置信度门禁） | ⚠️ 离线验证，未实机验收 | 真实窗口/DPI/遮挡表现未知 |
| RapidOCR 第二引擎（可选） | ⚠️ 新包未实测 | 缺失时静默跳过，不阻断主流程 |
| desktop 自动发送 | ⛔ beta 默认禁用 | `betaSafeMode` 默认 true；引擎/desktop/API/PS1 四层拒绝真实发送（已由 beta 构建与 15 条闸门用例验证） |
| phone-adb / windows-vm 通道 | 🧪 实验 | 代码保留，本轮未实机验证 |
| 表情包 | ✅ 部分通道 | desktop 通道暂不支持发送表情（UIA 表情面板未实现） |
| 人格广场（远程索引） | ✅ 需显式配置 | 仅当 `market.indexUrl` 非空；带 SSRF 防护；默认只用内置人格 |
| OCR 融合/对齐/跨帧差分（fusion/align/tracker） | 🧪 离线实验 | 已实现+单测，**未接入生产读取路径** |
| 插件市场 / 长期记忆 / 视觉模型 | ⚠️ 未来规划 | **不是** beta 功能 |

> `betaSafeMode` 已完整落地：`src/config.ts` 默认 `true`（旧配置迁移补 `true`）、`engine.canSend`/`processInner` 在非 mock 通道拒绝（LLM/搜索/记忆前早退）、`/test/send` 与 `/drafts/approve` 返回 409、桌面通道 `send()` 首行拒绝并给脚本追加 `-NoRealSend`、包内 `wechat-uia.ps1` 在找窗口/键鼠前硬阻断。
> 若你手上的构建缺少任一层的拦截，请把「真实通道发送」视为不可用，不要尝试在真实联系人上验证。

## 2. 已知限制

### 2.1 真实环境未验收

- 未在真实微信窗口上完成读取/OCR/发送的端到端验收；OCR 数字来自**合成语料 + 离线等价**，不代表真实聊天准确率。
- 未验证真实联系人切换、群聊、折叠窗口、多显示器/不同缩放、深色模式等边界场景。
- 未验证真实故障路径：DSH 重启、脚本超时、子进程崩溃、断电。

### 2.2 OCR 相关

- 合成语料 eval 集（46 条消息）结论：v3 CER 21.38% / 整句 47.83%；同集 v0.2.8 37.37% / 28.26%。改善主要来自 WinRT 2 倍放大 + CJK 空格归一；第二引擎融合与受控纠错在该语料几乎未触发。**样本小、为合成数据，不能外推真实聊天**。
- 小字体、高斯模糊、拉伸等困难场景仍明显偏低；表情/图片/语音不进文本管道。
- 详见 [OCR-BENCHMARK.md](OCR-BENCHMARK.md) 与 [OCR-ERROR-ANALYSIS.md](OCR-ERROR-ANALYSIS.md)。

### 2.3 版本与安装

- `package.json` 与 `src/index.ts` 已是 `3.0.0-beta.1`；**`dist/` 需重新构建后才会同步显示 beta 版本号**（`dist/` 不入库）。
- **betaSafeMode 等并行改动并入期间，仓库内的测试与 `verify:api` 可能短暂未同步**；以最终 beta 构建与发布说明为准，测试失败时不要启用真实通道。
- 未做干净机器/跨 OS 安装验证；Windows 为主目标平台。
- `npm pack` 会带入未跟踪文件，发布包必须按 [RELEASE-CHECKLIST.md](RELEASE-CHECKLIST.md) §6.4 用受跟踪文件制作。

### 2.4 安全与合规

- 自动化操作微信违反其协议，账号可能被限制/封禁；本项目不承诺规避风控。
- 公开仓库历史中可能存在疑似个人信息（审计见 [PRIVACY-REVIEW-PRE-RELEASE.md](PRIVACY-REVIEW-PRE-RELEASE.md)）。
- 不要用 beta 在真实联系人上做「验证性发送」；beta 默认安全模式正是为此设计。

## 3. 公开已知问题（无敏感信息）

1. dist 未重建时版本号显示旧值 `3.0.0`（构建即解决）。
2. 无 DSH configEditor 时设置页只读（宿主能力限制，非插件 bug）。
3. desktop 通道不支持发送表情。
4. phone-adb / windows-vm 通道参数与实机行为未在 beta 轮验证。
5. OFFLINE OCR 基准对 emoji、极短消息、重复文本仍不稳定。

> 上述限制会在后续版本逐步解除；当前 beta 不承诺这些项目可用。
