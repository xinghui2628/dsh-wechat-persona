# OCR 真实环境只读验证方案（v3.0.0 发布前验收）

> **状态：草案 — 等待维护者批准后才执行。**
> 本文档只描述计划，不代表已执行；本轮（发布前验收）不读取真实聊天、不向真实联系人发送。
> 参考任务书：`DSH_v3.0.0_发布前独立复核与只读验收_完整提示词.md` §5/§6/§11。

## 1. 目的

用**真实 Windows 与真实微信窗口**验证 v3.0.0 OCR 读取链路（截图 → OCR → 气泡归属 → 消息提取 → 身份/去重 → ack → 引擎入站）在真实字体、真实窗口尺寸、真实 DPI 下是否可用，并回答三个问题：

1. 真实截图下 OCR 的**漏读率/假消息率/归属错误率**是否可接受，是否达到「相对 v0.2.8 有可测量改善」；
2. 消息身份与去重（同一消息不重投、连发同文算两条、滚动不重触发、重启不重发）在真实窗口里是否成立；
3. 只读隔离是否从代码层保证：**不会发生任何真实发送**。

## 2. 前置条件（全部满足才可开始）

### 2.1 代码侧（发布前验收先证明，验证时复核）

- [ ] `readOnlyTestMode = true` 已写入配置并可持久化（重启不自动恢复真实发送）；
- [ ] 只读模式下：自动回复 / `/test/send` / `/drafts/approve` / 工具调用全部返回 `not-sent`，且 `channel.send` 调用计数为 0（有测试证据）；
- [ ] 只读模式不会执行输入框粘贴、回车、点击发送等键鼠模拟；
- [ ] 日志/状态/设置页明确显示「只读测试模式已开启」；
- [ ] `ocrPipelineMode` 可一键切 `legacy` 回退（出问题立即回退，不重装）。

### 2.2 环境

- [ ] Windows 10/11 + 微信 4.x 桌面版（单实例）；
- [ ] 语言包 `zh-Hans-CN` 可用（Windows OCR 依赖）；
- [ ] 屏幕缩放分别覆盖 **100% / 125% / 150%** 中至少两档（建议 150% 为主）；
- [ ] 记录宿主版本、微信版本、屏幕分辨率、DPI、插件版本（写入报告，不含本机路径/用户名）。

### 2.3 账号与数据（隐私红线）

- [ ] 使用**测试小号**，只与 **A / B / C** 三个虚构测试联系人对话；
- [ ] 聊天内容全部为虚构内容，**不出现真实姓名、真实手机号、真实地址、验证码、订单号**；
- [ ] 不进入任何私人/工作会话；不导出真实聊天记录；
- [ ] 截图、OCR 结果只落本机数据目录，**不上传**任何外部服务（含 LLM）。

## 3. 测试矩阵

每个场景使用虚构会话，记录：截图帧号、OCR 原始行、归属结果、最终消息 id、是否投递、ack 变化。

| # | 场景 | 目的 | 通过标准（建议） |
| --- | --- | --- | --- |
| T1 | 单条短句（「在吗」） | 基础识别/投递 | 1 条、文本一致、投递 1 次 |
| T2 | 长句（60+ 字，两行以上） | 跨行合并 | 合并为 1 条、不截断、不拆成多条 |
| T3 | 连发两条相同文本 | 身份稳定性 | 投递 2 条、id 不同、顺序正确 |
| T4 | 形近字/易错词（如 已/己、末/未 等形近字与标点差异） | 受控纠错边界 | 不误改姓名/数字；改动记入诊断 |
| T5 | 对方长气泡（>70% 窗宽） | 归属判定 | 判为对方（左），不得判成自己 |
| T6 | 自己发出的气泡 | 自回声 | 不投递、不回复自己 |
| T7 | 相似昵称（A1/A2、B/C） | 联系人验证 | 不串会话；无法确认则不回复 |
| T8 | 窗口滚动：先看历史再滚回 | 滚动不重触发 | 旧消息不重复投递 |
| T9 | 快速连发 3 条 | 不丢消息 | 全部投递、顺序正确 |
| T10 | 窗口遮挡/最小化后恢复 | 截图失败处理 | 不崩溃、不把空白当消息、自动恢复 |
| T11 | DPI 100%/150% 两档各跑 T1–T5 | 坐标模型 | 归属/行高不随 DPI 错位 |
| T12 | 重启插件（保持待确认 pending） | 重启不重发 | 不重复投递（本项依赖持久化已投递 id 修复） |
| T13 | 只读模式强制校验 | 安全隔离 | 发送入口全拒绝、`channel.send` 0 次调用 |
| T14 | 断网/微信未登录 | 错误处理 | 只报错不发送、状态 degraded 可恢复 |

## 4. 执行步骤

1. **S0 准备**：备份当前数据目录；确认 `readOnlyTestMode=true`；记录 HEAD/版本/环境参数；清空测试小号的非虚构会话。
2. **S1 基线**：用 v0.2.8 产物（`dist` 旧版本 / 独立 worktree）跑 T1–T5，记录指标作为对照。
3. **S2 v3（`ocrPipelineMode=v3`）**：同一批虚构会话跑 T1–T14，记录原始行/消息/诊断。
4. **S3 对照分析**：同场景对比 v0.2.8 与 v3（不漏/不重/归属/文本/CER 人工抽检）。
5. **S4 回退演练**：`ocrPipelineMode=legacy` 跑 T1–T3，确认可一键回退且不重装。
6. **S5 隔离证明**：全程监控 `channel.send` 调用计数与脚本 `-Action send` 调用次数，必须为 0；检查日志无「已发送」记录。
7. **S6 产出**：把结果填入 `docs/OCR-REAL-DEVICE-RESULTS.md`（新建，需授权后生成），并在发布清单逐条勾选。

## 5. 判定标准

- **安全项（任一失败即中止）**：出现任何真实发送 / 发送脚本被调用 / 读取真实私人会话 → 立即停止，回退 `legacy` 或关闭通道。
- **功能项（建议阈值）**：
  - 漏读率 ≤ 10%（虚构语料 20 条消息内）；
  - 假消息率 = 0（不得把头像/系统提示当消息）；
  - 归属错误 = 0（左右判定错误视为 P0，必须修复后才可继续）；
  - 重复投递 = 0（T3/T8/T12）；
  - 联系人串聊 = 0；
  - 消息 id 跨帧稳定（同一 pending 重放 id 不变）。
- **性能项**：单帧截图+OCR P50 ≤ 1.5s、P95 ≤ 3s（仅记录，不阻断；RapidOCR 第二引擎按需）。

## 6. 数据与隐私

- 验证结束后清理截图与数据目录（保留汇总指标）。

## 7. 风险与回滚

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 只读隔离有未覆盖入口 | 真实发送 | 中止；回退 `legacy`；修入口并补测试后才可重试 |
| 真实微信 OCR 与合成差异大 | 指标不达标 | 记录差异（字体/DPI/主题），给出修复方向，不强行发布 |
| 消息归属在真实长气泡上出错 | 发错人风险 | 视为 P0；`uncertain` 一律不回复，直至修复 |
| 窗口被抢占/前台切换 | 误点 | 只读模式禁止键鼠模拟，读取仅 `-NoSearch` 或已打开会话 |
| 断电/崩溃 | 状态不一致 | 数据目录可恢复；pending/ack 设计已支持重放，重启不重发待验证 |
